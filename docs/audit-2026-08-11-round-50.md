# Audit 2026-08-11 — Round 50

Round 50 independently audited the release-validation and localization layer after the Round 49 build/finalization hardening.

## Confirmed defects

1. `scripts/report-locale-parity.mjs` was diagnostic only. It reported duplicate, missing, and extra locale keys but always exited successfully, so CI could stay green with broken English/Russian parity.
2. Locale entries were trusted after JSON parsing even though runtime translation expects every entry to contain a non-empty string `message`. Malformed entries could reach `renderTemplate()` and fail at runtime.
3. The runtime uses named `{placeholder}` replacement, but CI did not require translated messages to preserve the English placeholder set. A translation could silently ship raw placeholders or ignore replacement values.
4. Locale parity was not part of the default `npm test` chain, so local validation differed from CI.
5. `npm run clean` did not remove `locale-parity-report.json`, and `.gitignore` ignored only `build/` rather than the normal blocker-only/Google build directories.

## Fixes

- Added reusable fail-closed locale catalog validation for duplicate/missing/extra keys, catalog/message schema, and named-placeholder parity.
- Kept `locale-parity-report.json` as a diagnostic report and preserved its established field names; the report is written before validation throws.
- Added Round 50 fixtures for clean split catalogs plus every confirmed failure class.
- Added locale validation and Round 50 checks to the default test/CI regression chain.
- Extended safe local cleanup to the generated locale report and ignored all normal `build*/` outputs plus the report.

No runtime extension behavior or product feature code was changed in this round.
