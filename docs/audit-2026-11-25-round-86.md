# Round 86 — render explicit UI changes when refresh fails

An explicit render coalesced with a storage refresh was lost when the refresh rejected. This can leave draft recovery controls, pending state or other local UI changes visually stale even though their page-local state changed. For explicitly requested renders only, use the last committed view if refresh fails and surface the original error. Conditional storage-only refreshes still avoid unnecessary DOM replacement. Preserve both errors when the fallback render also fails, keep the serialized queue reusable, and do not render after disposal. Round 39 fixtures cover conditional failure, coalesced explicit updates, dual failure, subsequent successful work and disposal.
