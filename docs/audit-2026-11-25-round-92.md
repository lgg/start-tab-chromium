# Round 92 — per-tab blocked navigation destinations

The blocked page previously retrieved a shared last URL per host, so two blocked tabs could reopen each other's paths or query strings. Track the original destination per tab in chrome.storage.session, serialize navigation, lookup and removal in each tab, wait for the preceding navigation event, validate the host and limit URL size. The actual blocked extension page may request only its sender tab's entry. A normal navigation or tab removal invalidates the entry; a worker restart retains session data. A missing entry (including older workers) falls back to the blocked host root, never another tab's URL. Historical lastBlockedUrls behavior and backup compatibility remain unchanged. Round 41 fixtures exercise concurrent tabs, queued lookup, worker restart, malformed host, failure and cleanup; static contracts verify message wiring. Real browser QA must verify DNR/webNavigation event ordering and sender.tab availability in supported Chromium builds.
