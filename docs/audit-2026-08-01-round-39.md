# Deep audit round 39 — clock targets and layout-editor concurrency

## Scope

Independent full-project continuation from exact `master` commit `bf65e3bbecd846dd8fd3711501bd2d25902d0c5c`. The audit rechecked every tracked source/configuration file, all declared extension pages and build profiles, current branch/PR state, historical regression contracts, per-instance runtime boundaries, asynchronous editor flows, storage-change behavior, durable clock alarms, accessibility state, localization parity, backup/sync transactions, and CI/release wiring.

## Confirmed defects

1. Round 38 added stale-target validation for Note, Local Tasks, Links, and Start Pinned runtime writes, but direct Timer, Stopwatch, and Pomodoro controls still acknowledged a removed or type-changed block as a successful no-op.
2. The Layout Editor refreshed its saved baseline after an external settings change while the editor was active but still clean, yet left the editable draft on the old snapshot. A later local edit could therefore be submitted with the new revision and overwrite the external change instead of conflicting or incorporating it.
3. Layout saving was not single-flight. Repeated Save activation left mutation controls live during the asynchronous write, allowing a second save or a new edit to race with the first and produce a false conflict or discard the later local interaction.
4. A block settings dialog could remain open while a clean editor accepted a newer external settings baseline. Submitting the old dialog result could then overwrite the newly refreshed block configuration.

## Corrections

- Extended the shared runtime target contract to all clock block types. Direct clock actions validate the target inside the same storage transaction.
- The clean active layout draft now refreshes together with its saved baseline; dirty or in-flight drafts remain stable for explicit conflict handling.
- Layout save is now single-flight. Save/cancel/mode/zone/palette and per-card mutation controls are unavailable until the write settles, then recover in `finally` on both success and failure.
- Block-dialog results are checked against the settings revision captured when the dialog opened and are rejected if an external baseline replaced it.
- Added Round 39 executable fixtures, static contracts, manual QA, audit documentation, CI wiring, and self-hosted contract coverage.

## Validation boundary

Automation covers clock target/type invariants, clean/dirty/in-flight draft policy, single-flight source contracts, revision checks, all historical regressions, TypeScript typechecking, and all three package profiles. Physical browser focus behavior, real cross-profile storage events, live Chrome alarm timing, and vendor-specific Chromium UI remain explicit interactive checks.
