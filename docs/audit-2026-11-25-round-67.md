# Round 67 — isolate runtime instance identities

Current-schema notes previously fell back to a key matching their type, e.g. "note". A legitimate note instance with that ID could silently populate other empty notes. Legacy clock normalization also copied type-keyed state to multiple timers, and current link pagination fell back to another instance's type-named ID.

Only legacy primary runtime schemas may interpret type aliases. A legacy alias belongs to the actual type-named instance when it exists, otherwise to the first instance of that type. Explicit per-instance values retain precedence; current-schema orphaned keys do not populate unrelated instances. Preserve the existing explicit legacy-sidecar fallback. Extend Round 54 fixtures to cover duplicate types, actual type-named IDs later in order, legacy migration and normalization idempotence.

Data already duplicated by an older build cannot be distinguished automatically from intentionally identical notes; do not destructively deduplicate it.
