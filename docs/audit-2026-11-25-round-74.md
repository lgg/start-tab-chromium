# Round 74 — coherent committed page snapshots

Storage events can publish a provisional higher runtime revision before a multi-step transaction rolls back. Do not accept the event payload as canonical or reject a legitimate rollback merely because its revision is lower. Read settings/runtime together under the data-write lock after migration, update both from that coherent snapshot, and use the same read for note conflict resolution. The render scheduler supports conditional refreshes so equal visible content updates the revision without DOM replacement; coalesced explicit renders and focus-stat changes still force rendering. Ignore a snapshot superseded by a local layout save and queue the post-save refresh. The regression holds a data-write lock while a provisional runtime is visible and verifies the reader returns only the restored state. Cross-process guarantees require Web Locks; fallback queues remain context-local.
