# Deep audit round 37 — full-project completion review

## Scope

Independent review of the exact `master` state after PR #114. The pass re-inspected every tracked source/configuration file and all declared user-facing surfaces: New Tab, onboarding, inline layout editor, Options, popup, blocked page, early disabled/Split View gate, service worker, settings/runtime storage, local backup/import/recovery, Browser Sync, Google Calendar/Drive, weather, localization, permissions, release documentation, build profiles, and the historical validation chain.

## Confirmed defects

1. **Split View marker policy had diverged.** The service worker accepted additional markers that the early gate did not, while also accepting generic tokens such as `split`, `picker`, and `pane`. That could either redirect a real browser Split View picker incorrectly or bypass Start Tab for an unrelated internal URL.
2. **Onboarding did not restore focus.** It moved keyboard focus into a modal but removed the modal without returning focus to the control that previously owned it.
3. **Onboarding and the early gate did not share a complete dismissal lifecycle.** The gate removed onboarding directly, bypassing onboarding-owned focus/inert cleanup. Rapid onboarding actions could also submit the same transactional operation twice.
4. **Weather day/week mode could render a blank card.** A successful provider response with no complete daily rows replaced the loading state with an empty weather container instead of the localized unavailable state.
5. **Invalid timed Calendar events were mislabeled as all-day.** A damaged or missing parseable timed start fell back to the all-day label even when the provider did not declare the event all-day.
6. **Untitled Google Calendar events were not localized.** The data layer injected the hard-coded English string `Untitled event`, so Russian UI could display English text and whitespace-only titles could remain blank.
7. **Global Commands resets lacked confirmation.** “Reset all clocks” and “Reset focus statistics” executed immediately, unlike the equivalent destructive settings action.
8. **The exposed `confirmDeleteWithContent` setting was not implemented.** Note and Local Tasks editors persisted the checkbox, but block deletion ignored it. In addition, progressed Timer/Stopwatch/Pomodoro runtime was not recognized by the single-block deletion warning.
9. **Official documentation contradicted the product.** README still described pre-PR-114 queue behavior, and `docs/release-3.0.0.md` instructed users to set Google OAuth while running the ordinary build even though only `npm run build:google` consumes it.
10. **Build validation omitted a required static asset.** `blocked.html` references `icons/icon.large.png`, but the build validator did not prove that the asset was present in every package profile.

## Corrections

- Added one explicit Split View marker policy for service-worker logic and made the early gate use the same complete marker set. Removed generic `split`, `picker`, and `pane` bypasses.
- Added onboarding-owned dismissal, previous-focus restoration, `aria-describedby`, action disabling, and a double-submit guard. The early gate now dispatches a synchronous dismissal event before its fallback DOM removal, so focus and shared `inert` state remain correct.
- Day/week weather rendering now requires at least one complete forecast row and otherwise keeps the localized unavailable fallback.
- Calendar rendering now localizes empty titles and never labels a damaged timed event as all-day. The Google data layer preserves empty titles for the locale-aware renderer.
- Commands now confirms both global clock reset and focus-statistics reset before sending mutations.
- Implemented `confirmDeleteWithContent` for Note and Local Tasks while preserving the generic delete confirmation when the stronger warning is disabled. Progressed clock instances now receive the saved-data warning.
- Corrected README concurrency wording and the legacy 3.0.0 Google build instructions; release validation now protects the latter.
- Build validation now requires `icons/icon.large.png` in full, blocker-only, and Google-enabled outputs.
- Added Round 37 executable fixtures, static contracts, CI/self-hosted wiring, locale strings, and expanded manual QA.

## Validation strategy

Round 37 fixtures cover explicit/generic Split View markers, Calendar title/date fallbacks, weather day/week selection, Note/Task deletion-warning preferences, and progressed clock deletion. Static contracts cover modal lifecycle coordination, destructive-command confirmation, documentation/build promises, locale parity, and exact CI wiring.

The final clean head is intended to run exactly one self-hosted validation after the draft PR is moved to Ready for review. That run must execute the complete historical regression chain through Round 37, TypeScript typecheck, full build, blocker-only build, Google-enabled build, and bounded cleanup.

## Validation boundary

Repository automation can prove deterministic source contracts, storage/runtime transformations, marker semantics, locale parity, type safety, and package contents. It cannot prove browser-vendor Split View internals, physical focus behavior in every Chromium fork, live weather/Google services, production OAuth consent, Chrome Web Store review, or real cross-device timing. Those remain explicit manual release checks.
