# Round 96 — protect incomplete remote Browser Sync frames

Chrome Sync can deliver metadata and data chunks independently. Smart Sync formerly treated unparseable metadata as absence and could overwrite a partial remote frame. Require absence of the metadata key and nonempty numbered chunk slots both on the initial quota read and immediately before committing a missing-frame smart upload. A valid newly arrived frame still triggers the existing conflict/recalculation path; explicit Upload remains the intentional repair operation, subject to existing future schema and revision checks. The existing verified matching-frame repair is unchanged. Round 32 fixtures cover malformed metadata, orphan chunks, late replication, intentional repair and empty reserved chunk slots. Chrome Sync is not a distributed CAS service; a remote device can still race a final write.
