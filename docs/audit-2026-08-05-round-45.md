# Deep audit round 45 — failed rebuild output invalidation

## Scope

Independent continuation from exact `master` commit `41430e0533936525ac4ff2e4db8ae3d1c85faad4`. The audit rechecked the complete esbuild lifecycle after Round 44: initial builds, long-running watch rebuilds, JavaScript bundles, copied static assets, missing recursive source trees, compile failures, finalization failures, profile boundaries, and bounded output cleanup.

## Confirmed defects

1. Generated-output cleanup ran only during successful `onEnd` finalization. An early compilation or watch-input failure therefore left the previous JavaScript bundles and static extension files in `build/`, even though they no longer represented the current source tree.
2. Removing the root `icons/` or `src/_locales/` directory caused the static watch plugin to fail while collecting inputs before static cleanup ran. The old generated tree remained loadable and appeared current.
3. A TypeScript syntax or resolution failure similarly left the previous bundle set in place.
4. If compilation succeeded but static copying or manifest transformation failed, esbuild bundles and any already-copied assets could form a partial mixed-version output.

## Corrections

- Added one profile-aware generated-output list containing every esbuild bundle and every copied static target.
- Added a reusable lifecycle plugin that invalidates generated outputs in `onStart` before every build attempt.
- Compilation and watch-input failures now leave generated extension outputs absent rather than silently stale.
- Successful compilation still performs production-graph validation and static finalization.
- Any finalization failure triggers a second bounded invalidation pass, removing new bundles and partial static files.
- Cleanup failures are reported together with the original finalization failure through `AggregateError` instead of hiding either cause.
- Unrelated files inside the output directory remain untouched, and blocker-only invalidation does not remove full-profile-only new-tab outputs.
- Added real esbuild fixtures for compile failure, finalization failure, successful recovery, profile separation, and unrelated-file preservation.

## Validation boundary

Automation proves lifecycle behavior with actual esbuild builds and permanent static contracts. Physical Chromium QA remains useful to verify that an unpacked extension visibly becomes unavailable after a failed rebuild and returns only after the source is restored and a complete successful rebuild finishes.
