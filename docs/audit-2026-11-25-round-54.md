# Round 54 — stable block/theme identity and optimistic edit revisions

Base: 41af4f69cf7c933cc41a7d2e8c0028db681d84a5.

## Confirmed defects
- Appending a suffix to a 160-character duplicate block/theme ID generated a value longer than the input normalizer allowed. Once the original entity was removed, the remaining ID could be truncated and its associated notes, timers, tasks, or selected-theme reference could be lost.
- A generated duplicate suffix could steal a later explicitly supplied ID, causing unrelated block or theme identity to change.
- Free-mode geometry defaults derived from the maximum grid row could exceed the allowed free-mode coordinate; the next normalization silently changed the result.
- Theme saves stamped Date.now() directly. Same-millisecond saves or a wall-clock rollback could leave a stale optimistic edit accepted. A block with a newer imported entity timestamp than its settings root could suffer the same equality collision.

## Corrections
- Shared bounded ID generation, reserving explicit IDs before collision repair. Preserve legacy numeric-suffixed IDs previously emitted by the application (up to 165 characters) and their selected theme references; new generated suffixes fit 160 characters.
- Clamp fallback numeric values through the same range validation as supplied values.
- Advance a changed existing block/theme entity revision beyond its prior value even when wall-clock time has not advanced; reject unsafe integer exhaustion.
- Add Round 54 executable fixtures to npm test and the Windows CI contract. Fixtures exercise duplicate long IDs, reserved explicit IDs, legacy note data and selected theme, idempotency, free-mode bounds and stale same-millisecond edits.

## Validation boundary
Malformed external data with truly identical duplicate IDs is intrinsically ambiguous; preserve the first explicit identity and assign distinct safe IDs to the rest. Existing valid persisted legacy suffixes are not renamed. Real drag/resize and browser QA remain separate release checks.
