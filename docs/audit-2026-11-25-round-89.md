# Round 89 — committed runtime and statistics reads

The public runtime getter previously returned an already normalized value without waiting for the shared transaction lock, and read settings and runtime separately. A provisional clock, layout or backup write could therefore appear in a widget even if the enclosing operation rolled back. Read both keys under data-write, retain future-schema read-only behavior and the transient editor projection. The public statistics getter now also waits for that lock instead of exposing provisional statistics. Internal transaction helpers remain non-reentrant. Round 16 regressions hold the lock, publish normalized provisional runtime/statistics, roll back and verify both public readers return the committed values, and verify that a projected layout cannot prune saved runtime.
