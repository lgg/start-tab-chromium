# Deep audit round 44 — exact static output replacement

## Scope

Independent continuation from exact `master` commit `3dfc64c218bcb448c584e702bb0d31b15daf2031`. The audit rechecked the Round 43 watch implementation, output-path safety contracts, copied static assets, full and blocker-only profiles, long-running rebuild behavior, and CI regression wiring.

## Confirmed defects

1. Round 43 removed and recopied the recursive icon and locale trees, but explicit generated files such as `manifest.json`, HTML, CSS, and `newtab-gate.js` were only overwritten. If one of their source files disappeared or a copy failed, the old generated file could remain in the unpacked extension and falsely look current.
2. Build-output link safety was validated only when the process started. A long-running watch process did not revalidate the output path immediately before later recursive cleanup and static writes.
3. A final generated path replaced with a junction or symbolic link after startup could be followed by a later file copy or manifest write unless that generated target was removed safely first.

## Corrections

- Added one profile-aware list of every generated static output.
- Revalidate the output filesystem before every static copy, recreate the output directory if needed, and validate it again after creation.
- Remove every generated static target through the bounded link-aware cleanup helper before copying or writing the new revision.
- Preserve JavaScript bundles while making every copied static file and directory exact: failed copies leave the affected generated target absent rather than silently stale.
- Added executable Round 44 fixtures for full and blocker-only output sets, stale explicit files, final junction removal, external-data preservation, and output-directory link substitution.
- Updated the historical Round 43 contract to accept the stronger delegated cleanup implementation and wired Round 44 into npm and CI.

## Validation boundary

Automation verifies exact generated-output removal, profile separation, link rejection, external target preservation, static contracts, historical regressions, TypeScript typecheck, and all three production build profiles. Physical Chromium QA remains useful for confirming that a failed watch rebuild visibly removes the stale generated asset and that restoration produces a clean reloadable extension.
