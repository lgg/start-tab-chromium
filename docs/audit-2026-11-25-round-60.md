# Round 60 — provider responses and bounded network requests

- Widget fetches have an eight-second per-request deadline (including response-body consumption); Google API requests have a thirty-second deadline. A timed-out write is not automatically retried because the server may have committed it. Interactive OAuth itself remains user-driven.
- Validate IP address syntax and provider failure flags before accepting a response. Invalid responses no longer suppress fallback providers.
- Weather response normalization validates finite temperatures, weather codes, real calendar dates, range order and duplicate days; rejects empty/error payloads. Invalid all-day calendar dates no longer roll into the next month.
- Share pending requests in a bounded widget cache, expire completed entries relative to actual successful response time, and clear rejected loads.
- Validate Google Calendar listing shape and defensively normalize individual event fields; handle empty/absent OAuth tokens.
- Extend Round 34 fixtures. No actual network provider/OAuth requests were executed by the regression fixtures; real browser acceptance remains required.
