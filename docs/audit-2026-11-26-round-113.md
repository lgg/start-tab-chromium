# Round 113 — blocked destination sender validation

The worker previously accepted any sender URL sharing the blocked-page pathname, without checking its query host, frame or live navigation. Require a top-level active blocked document, one matching site parameter, and a matching current tab before and after the queued per-tab lookup. Return no destination when the tab is unavailable or changes. The blocked page retains its safe host-root fallback. This does not create an atomic browser navigation transaction or distinguish two successive documents with identical URLs; real Chromium navigation testing remains required.
