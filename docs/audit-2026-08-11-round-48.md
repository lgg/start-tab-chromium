# Deep audit round 48 — static finalization race safety

## Scope

Independent continuation from exact `master` commit `eac78804deb1ea0bce74956a670180dd479a84de` after the Round 47 merge. The audit rechecked the complete Round 43–47 static watch/build lifecycle, source validation, output path-safety, profile exactness, and failure cleanup behavior instead of assuming the previous green CI run covered every interleaving.

## Confirmed defects

1. Round 47 moved shared static source validation into `copyStaticAssets()`, but the lifecycle output-path revalidation still happened before calling that function. The asynchronous source scan therefore reopened a window in which `outdir` could be replaced with a junction/symlink after the supposedly final guard and before the first static write.
2. Static copy phases used `Promise.all(...)`. If one `cp()` rejected quickly, sibling copies continued running even after the promise rejected. Lifecycle cleanup could therefore finish while a sibling writer was still active, allowing that late writer to recreate a generated file or directory after failure cleanup.
3. Round 47 validated recursive `icons/` and `_locales/` trees but did not `lstat()` explicit static files such as `manifest.json`, HTML/CSS, and `newtab-gate.js`. Missing explicit files reached the copy phase, and explicit links/special entries were not rejected by the same structured source-input contract.
4. Generated-output removal passed the mutable `outdir` itself as the cleanup boundary. Although `outdir` was checked before the loop, each `removePathWithinBoundary()` call therefore treated that path as already trusted instead of rechecking it as an intermediate segment from the trusted repository/temp root.

## Corrections

- Add a guarded static-output writer that revalidates the build output immediately before every individual copy and transformed manifest write.
- Serialize static copy batches so an error cannot escape while another copy is still in flight.
- Validate explicit static assets with `lstat()`; require regular files, report missing files separately, and retain parent directory watches for automatic recovery.
- Preserve recursive static-tree link/wrong-type rejection and combine both explicit and recursive invalid inputs into one fail-visible contract.
- Make generated-output removal start from the trusted repository/temp boundary, so the selected `outdir` is inspected as an intermediate path on every removal.
- Keep Round 44–47 historical guarantees intact while evolving their static contracts to the stronger Round 48 implementation.

## Regression coverage

Round 48 adds executable coverage for linked explicit static assets, missing explicit-file recovery in the same real esbuild watch process, output replacement after source validation but before the first static write, and a delayed successful static write followed by a copy failure to prove lifecycle cleanup does not race an in-flight sibling writer. Static contracts also require trusted-root cleanup wiring, per-write output guards, serialized batches, full/blocker/Google build coverage, npm wiring, and self-hosted CI coverage.
