# Deep audit round 41 — navigation, gate, and popup race hardening

## Scope

Independent continuation from exact `master` commit `796fe09e367f5e6df9b28f3f712ed3673c46a7b7`. The audit rechecked all 267 tracked files, every declared extension page and block type, fallback new-tab ownership, early gate initialization, popup actions, settings/runtime/background transactions, blocker flows, backup and sync paths, OAuth-gated integrations, localization, accessibility contracts, manifests, documentation promises, and all three build profiles.

## Confirmed defects

1. The service worker handled every `chrome.tabs.onUpdated` event using `changeInfo.url ?? tab.url ?? tab.pendingUrl`. Status, title, favicon, or loading updates could therefore re-run the fallback redirect without a navigation. Because the native-new-tab bypass was consumed only once, a browser-owned new tab opened intentionally from Start Tab could later be redirected back to Start Tab by an unrelated update.
2. The early new-tab gate allowed overlapping locale catalog loads and settings/split-view applications to finish out of order. A slower stale operation could replace the newest catalog or overlay state. Its storage listener was also registered only after the initial catalog load, leaving a startup window in which a settings or locale change could be missed.
3. The popup rendered one active tab and block state, then reused that captured target when the user clicked later. A tab switch, navigation to another host, or external blocklist change could make the displayed action stale. Concurrent popup actions and overlapping renders were not coordinated.

7. Self-hosted CI downloaded `actions/cache` before any repository step. Under disk pressure this prevented the bounded cleanup script from starting, creating a retry loop that could not repair itself.

## Corrections

- Added an explicit URL-transition filter for `tabs.onUpdated`; status-only and metadata-only events no longer enter fallback redirect logic.
- Changed native-new-tab bypass consumption into a short lease. Repeated URL events for the same tab remain bypassed until expiry, while other tabs and expired markers remain rejected.
- Added generation guards to locale catalog loading and gate application. Only the newest asynchronous operation may commit catalog, overlay, inert, focus, or gate-change state.
- Registered the gate storage listener before the first asynchronous catalog load.
- Reworked popup actions to re-resolve the active tab, host, and current block state immediately before mutation. Stale actions are rejected and the popup rerenders the actual target.
- Added popup single-flight state, disabled controls during startup and mutations, and generation-protected asynchronous rendering.
- Added localized stale-target feedback in English and Russian.
- Added executable Round 41 fixtures, static contracts, manual QA, CI wiring, and self-hosted CI contract coverage.

## Validation boundary

Automation verifies repeated native-tab bypass consumption, explicit URL-only redirect handling, generation-token presence and ordering, popup target equality and stale-state rejection, localization parity, historical regression contracts, TypeScript typecheck, and all build profiles. Physical Chromium validation is still required for vendor-specific native-new-tab URLs, real tab focus timing, browser popup lifecycle, Split View UI variants, and production OAuth accounts.
