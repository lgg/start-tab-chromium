# Round 114 — nested backup container validation

A syntactically valid primary section could contain damaged nested collections, e.g. layout.blocks as a string, runtime notes as arrays or task dictionaries with scalar entries. Normalization would silently replace these with default or empty content. Validate known present container and entry shapes before strict migration/import while leaving missing legacy fields and explicit empty collections accepted. Local recovery export still uses its tolerant normalizer. Tests verify malformed payloads never touch local data, alarms or rules, and historical and actual exported backups still migrate. This is shape validation, not an exhaustive semantic or cryptographic integrity guarantee.
