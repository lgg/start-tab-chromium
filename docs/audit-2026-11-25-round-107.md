# Round 107 — verify differing remote frames before Smart Sync

A remote metadata record can arrive before all of its chunks. The differing-checksum path previously allowed a newer local revision to overwrite an incomplete or corrupt remote frame without verifying it. Require full checksum/payload and metadata verification before selecting a direction. Preserve matching-content repair and explicit Upload. Fixtures cover absent, empty and damaged chunks with newer local state, plus an intact frame that still uploads normally. Chrome Sync has no distributed compare-and-swap primitive; this protects the observed frame, not every possible replication race.
