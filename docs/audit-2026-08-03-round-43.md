# Deep audit round 43 — static watch coverage and explicit CI regression steps

## Scope

Independent continuation from exact `master` commit `a3326afa9d0a713582c58cfc8673486fc3448f7a`. The audit rechecked repository and branch state, the latest merged onboarding changes, build profiles, the self-hosted Windows workflow, production-graph checks, source/static asset boundaries, and the development watch path.

## Confirmed defects

1. `npm run watch` delegated file invalidation entirely to esbuild's imported module graph. Extension assets copied outside that graph — HTML, CSS, `manifest.json`, locale catalogs, icons, and `newtab-gate.js` — did not trigger a rebuild when edited. The generated unpacked extension could therefore remain stale while the watch command continued running.
2. Recursive icon and locale directories were copied over the existing generated directories. A source file removed during watch mode could therefore survive as a stale copied file under `build/icons/` or `build/_locales/`.
3. Round 42 fixtures and static contracts were executed only as side effects of `validate-self-hosted-ci.mjs`. The workflow step list stopped at Round 41, while the PR and audit documentation described a complete chain through Round 42. The checks did run, but the workflow contract did not require explicit latest-round commands, reducing visibility and making future omissions easier.

## Corrections

- Added one esbuild watch plugin that registers every copied static file through `watchFiles` and the relevant directories through `watchDirs`.
- Kept blocker-only behavior exact: new-tab assets are not watched or copied in that profile.
- Watch discovery rejects special filesystem entries inside recursive icon/locale asset trees instead of silently treating links or device entries as extension assets.
- Generated icon and locale directories are removed and recopied after every successful build, so deletions cannot leave stale output behind.
- Added deterministic Round 43 fixtures for full and blocker-only watch sets, nested assets, unique paths, directory coverage, plugin registration, and a real esbuild injection smoke test.
- Added permanent static contracts for watch-only injection, exact copied-tree replacement, documentation, npm wiring, and explicit CI ordering.
- Promoted Round 42 to dedicated workflow steps and added dedicated Round 43 steps. The self-hosted CI validator now requires both rounds directly instead of importing Round 42 as a hidden side effect.

## Validation boundary

Automation verifies static asset discovery, profile separation, plugin registration, copied-tree replacement contracts, explicit CI commands, historical regressions, TypeScript typecheck, and all three production build profiles. Physical watch-mode QA remains required to observe a live Chromium unpacked extension updating after representative HTML, CSS, manifest, locale, icon, and early-gate edits.
