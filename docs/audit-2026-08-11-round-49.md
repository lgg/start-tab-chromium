# Deep audit round 49 — guarded bundle and source finalization

## Scope

Independent continuation from exact `master` commit `b6ab535ed7cd09f7a92b231989caf25f5095f87c` after Round 48. The audit rechecked the complete generated-output lifecycle, with special focus on what still happened between `onStart` cleanup and `onEnd` finalization, and on source paths that were consumed after the Round 48 whole-tree validation had already completed.

## Confirmed defects

1. JavaScript bundles were still written directly by esbuild with its default `write: true`. A safe `outdir` could therefore be replaced after lifecycle `onStart` and receive `service-worker.js`, `popup.js`, `blocked.js`, `options.js`, or `newtab.js` before the Round 47/48 post-compile filesystem revalidation ran. Static assets were guarded, but JavaScript bundle output remained an unguarded JavaScript bundle path.
2. Round 48 whole-tree source validation was still a snapshot. Explicit assets, the transformed `manifest.json`, or recursive `icons/` / `_locales/` roots could be replaced after that scan and before their later `cp()` / `readFile()` operation. This left a source-side validation window symmetrical with the output-side window Round 48 had closed.
3. The generated bundle contract assumed the current exact filenames but did not verify the set returned by esbuild before materialization. A future unexpected chunk or map could fall outside the known cleanup universe unless finalization failed closed.

## Corrections

- Configure production esbuild with `write: false`, keeping JavaScript bundle bytes in memory until lifecycle finalization.
- Add a lifecycle bundle-finalization callback after graph/static-input preflight and fresh output-filesystem validation.
- Require the returned esbuild output set to match the exact profile-owned bundle paths before writing any bundle.
- Materialize accepted bundles sequentially through the guarded output writer, which rejects destinations outside the selected `outdir` and revalidates output filesystem safety before each write.
- Add per-operation static source validation. Explicit files are `lstat()`-checked again before copy/read; recursive roots are rescanned for regular-file/directory-only structure immediately before recursive copy.
- Route transformed manifest reads through the same per-source guard instead of calling `readFile()` directly after an older preflight.
- Preserve the Round 45–48 fail-closed cleanup, profile exactness, missing-source recovery, and static-copy serialization guarantees.

## Regression coverage

Round 49 adds executable fixtures for explicit-source replacement after whole-tree validation, manifest replacement before read, recursive-root replacement before `cp()`, missing/unexpected in-memory bundle outputs, late output junction/symlink replacement immediately before bundle materialization, and successful materialization of a real esbuild `outputFiles` result. The permanent static contract also requires `write: false`, exact bundle-set validation, per-source guards, lifecycle ordering, npm wiring, and self-hosted CI coverage.
