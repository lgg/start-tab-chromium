# Round 105 — destructive command safety

Reset commands formerly had no shared in-flight lease. Rapid activation, duplicate command widgets or a rebuild could submit overlapping resets; resetting clocks also awaited a direct runtime read after the worker committed, falsely reporting mutation failure if that read failed. Use one page-wide lease for destructive commands, disable all registered controls including replacements, ignore detached buttons, and queue canonical refresh independently on settlement. Cancel does not mutate. Regression fixtures cover concurrent commands, replacement controls, cancellation and rejected writes. Cross-tab operations remain serialized by the worker/storage layer.
