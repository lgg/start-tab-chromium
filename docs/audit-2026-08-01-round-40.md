# Deep audit round 40 — Options concurrency and completion truthfulness

## Scope

Independent continuation from exact `master` commit `b0df4fdcef634534c26cb84e63d5f806a4d7e85c`. The audit rechecked all 261 tracked files, every declared extension page and block type, settings/runtime persistence, destructive actions, block and theme editors, backup/sync/Google paths, localization parity, manifests and three build profiles, documentation claims, and the complete historical regression chain.

## Confirmed defects

1. Options block and custom-theme dialogs applied their result to the latest stored entity without proving that the entity shown when the dialog opened was still current. A stale dialog could silently overwrite a newer edit or recreate a theme deleted elsewhere.
2. Stale Enable/Disable and Duplicate controls operated on the latest block/theme while their label and preview described an older snapshot. This could invert newer state or duplicate data the user had not reviewed.
3. Clear instance data carried only an instance ID. It could erase runtime changed in another Start Tab after the confirmation, or runtime belonging to a block whose configuration had since changed.
4. Options allowed overlapping mutations. Rapid repeated activation could create duplicate writes, false conflicts, or multiple duplicates.
5. On a failed Options mutation, the page kept its stale in-memory state instead of reloading the canonical state, encouraging repeated conflicts.
6. The historical roadmap implementation document still displayed all completed 3.0.0 requirements as unchecked while the README correctly declared the roadmap complete.

## Corrections

- Added item-revision guards to block edit/toggle/duplicate and theme edit/duplicate/delete operations. New-theme creation remains supported, while a stale editor can no longer resurrect a deleted theme.
- Clear-instance-data messages now require both the displayed block revision and runtime revision. The service worker validates both under the same storage lock before deleting runtime or alarms.
- Added one single-flight Options action guard and made the header, navigation, and sections inert/`aria-busy` during a mutation.
- Options now reloads and rerenders canonical state after both successful and failed mutations; combined action/refresh failures remain visible.
- Marked the completed roadmap checklist as complete and recorded Round 40 reverification.
- Added executable Round 40 concurrency fixtures, static contracts, targeted manual QA, npm/CI wiring, and self-hosted CI contract coverage.

## Validation boundary

Automation verifies stale block/theme rejection, non-resurrection, exact runtime-clear revisions, single-flight recovery, message validation, documentation truthfulness, historical regressions, TypeScript typecheck, and all build profiles. Real browser focus/inert behavior, native confirmation dialogs, real cross-profile storage races, OAuth accounts, and vendor-specific Chromium UI remain explicit interactive checks.
