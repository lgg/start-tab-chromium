# Round 58 — note draft ownership and conflict recovery

Based on the Round 57 candidate tree.

## Defects
- Per-render debounce queues were discarded and recreated during layout, locale or runtime refreshes. A second renderer could use a stale/optimistic baseline and lose newly typed text.
- Failed CAS writes reloaded canonical storage but silently discarded the unsaved note text.
- Page unload warned only for layout edits, not for an in-flight/unsaved note.
- Full rebuilds removed focus and selection from a note during typing.

## Corrections
Keep one page-scoped draft/acknowledgement state and save queue per note instance, retaining the exact worker CAS baseline and pending text across DOM rebuilds. Failed saves preserve the draft and offer explicit retry or discard. Re-read actual canonical state before retry, and require confirmation if retry would overwrite a different saved value. The worker's CAS remains authoritative. Warn on beforeunload for pending/failed drafts and best-effort flush on cleanup. Restore note focus/selection across ordinary render rebuilds.

Unit regressions exercise in-flight edits, rebuilds, stale acknowledgements, conflicts, explicit retry/discard and reverting while a save is in flight. Real browser interaction and extension termination tests remain required. No claim of crash-proof persistence is made: browser close can interrupt asynchronous I/O and browser unload prompts are not guaranteed in every environment. If a note block is deleted externally, the draft remains in page memory, but the missing block cannot be saved until restored.
