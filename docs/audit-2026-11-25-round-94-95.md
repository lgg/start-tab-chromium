# Rounds 94–95 — committed settings reads and complete Calendar results

Public settings reads used to return normalized storage without waiting for the data-write transaction. A failed layout or restore operation could temporarily enable/disable the native-tab fallback or show provisional migration details. All public settings and migration-report reads now acquire the lock; the internal read-only snapshot helper remains available inside transactions.

Calendar previously silently returned a partial or empty result after a repeated or malformed pagination token or the page budget. An exhausted valid listing or a full widget remains successful, but incomplete pagination now reports the existing unavailable state and can retry on the next render. Tests cover rolled-back settings/report reads, real empty and short result sets, repeated/malformed tokens, bounded pagination and a filled widget. Manual browser QA remains necessary for live Google OAuth/Calendar and actual native-tab behavior.
