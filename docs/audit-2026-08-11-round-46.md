# Deep audit round 46 — watch recovery and startup cleanup

## Scope

Independent continuation from exact `master` commit `dd48dc20b1d4bc3352500dfe7ca956ab3703f0f8`. The audit rechecked the Round 43–45 static-watch/output lifecycle, startup cleanup behavior, missing recursive asset roots, recovery after failed watch builds, CI regression wiring, and preservation of unrelated output files.

## Confirmed defects

1. `scripts/build.mjs` still recursively removed the whole selected output directory before esbuild started. That bypassed the Round 45 bounded generated-output lifecycle and deleted unrelated files even though rebuild cleanup intentionally preserves them.
2. `collectStaticAssetWatchInputs()` threw immediately when the root `icons/` or `src/_locales/` directory was missing. The failing `onLoad` therefore could not return durable recovery watch metadata.
3. The parent of the root `icons/` directory was not explicitly watched. Recreating `icons/` after a failed rebuild could therefore require an unrelated source edit before watch mode noticed the repair.
4. `validate-self-hosted-ci.mjs` had not advanced its regression command list through Round 45, so the self-hosted CI contract no longer independently required the latest explicit regression steps.

## Corrections

- Removed broad startup deletion of the output directory. Startup now relies on the same profile-aware, link-safe generated-output lifecycle used by every rebuild.
- Missing recursive static roots are collected as explicit build errors instead of escaping from the watch plugin.
- The repository root and source root remain watched so recreation of `icons/` or `_locales/` triggers recovery automatically.
- Missing directories themselves are not registered as existing watch directories; their existing parents carry the recovery watch.
- Added a real esbuild `context.watch()` fixture proving missing `icons/` -> failed build -> directory recreation -> automatic successful rebuild, then deletion and restoration again without a source-code edit.
- Added startup preservation coverage proving generated files are removed while unrelated output survives.
- Advanced the self-hosted CI contract through Rounds 45 and 46.
