# Round 56 — stale new-tab events and independent startup reconciliation

Base: e399349ee6e4c5da0806dbda1fb405ade28cd84a.

## Confirmed defects

- The service worker used an event URL after asynchronous lease and settings reads, then called tabs.update without checking that the tab was still on the same native new-tab page. A user navigating to another site could be redirected back to Start Tab.
- onCreated preferred the committed URL over the pending destination.
- Closing a tab or receiving a newer non-new-tab URL did not cancel a pending redirect.
- Startup reconciliation was a single fail-fast sequence. A layout/runtime or alarm failure skipped DNR rule repair; a blocker migration failure skipped clock recovery.

## Corrections

Per-tab outstanding tokens invalidate older work on every explicit navigation and tab removal. A fresh tabs.get is required before the lease read and immediately before update; pendingUrl is preferred, missing/closed tabs fail closed, and unrelated tab attempts remain independent. The native bypass and disabled/split-view checks are preserved. Startup runs independent migration/reconciliation effects even if another effect fails.

Extended existing Round 41 executable and static contracts. The browser API does not offer an atomic conditional tabs.update; an unseen navigation after the last live read remains an API limitation. Real browser QA is needed for native-tab and split-view behavior.
