# Round 57 — clock retries, countdown feedback and page lifecycle

Base: 2e4582f327ba6bd4430b9ccbfd1bf0e169562704.

## Defects
- A failed automatic completion called update immediately; with an expired token still in memory, update launched another request without waiting. Request pending was also released before the refresh finished, and lost during DOM rebuilds.
- Blocked-page errors were written into the countdown element immediately hidden by the failure handler, so the user got no visible explanation.
- Counting interval callbacks stretched the 10-second delay when the browser throttled the tab.
- Restored BFCache pages retained disposed widgets/listeners or a stopped countdown.

## Corrections
- Page-scoped per-instance clock request leases survive DOM rebuilds, remain held through refresh, and apply a one-second monotonic retry delay to each finished completion token. Manual actions remain available outside a live request. Disposed renderers no longer dispatch new requests.
- Visible accessible error region remains independent of retry controls.
- Countdown uses a monotonic deadline; elapsed time, not callback count, determines completion.
- Reload BFCache restores of disposed new-tab or blocked pages to reconstruct state.

Extended existing Round 35 fixtures and static contract. Real Chrome/Edge lifecycle and timer testing remain manual acceptance tasks.

Also guard repeated Add Task submissions while the worker is pending, preserve a newer typed draft after an acknowledgement, and round countdown displays upward until the actual deadline. The task submission gate is scoped to its form; persistent drafts across arbitrary page rebuilds remain a separate UI concern.
