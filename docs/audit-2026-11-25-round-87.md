# Round 87 — separate successful legacy runtime writes from refresh failures

An older worker may return a successful acknowledgement without a runtime revision. The task and link-page renderers then read a coherent snapshot. When that follow-up read failed, an already committed task addition was treated as a failed write, leaving its draft ready to submit again. Handle that refresh as an independent operation only after success, display a localized saved-but-refresh-failed warning, clear only the acknowledged draft generation, and keep the normal settle-triggered refresh. The mutation's own failure still rejects and retains the draft; compare-and-set checks still protect subsequent writes against stale baselines. Round 35 tests cover failed and successful post-commit refresh and acknowledged draft clearing.
