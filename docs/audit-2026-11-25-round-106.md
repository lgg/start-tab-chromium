# Round 106 — bounded Google metadata and response cleanup

Google list and write-ack responses formerly read the entire response into memory, including unnecessary Calendar event descriptions/attachments, and abandoned failed HTTP bodies without cancellation. Request only the fields needed for Calendar display and pagination. Bound decoded metadata bytes to 4 MiB, cancel rejected streams without awaiting cancellation, and discard HTTP error bodies before token retry or error reporting. Explicit Drive media restores retain their existing size behavior to avoid imposing an incompatible backup limit. Fixtures cover streamed overflow, authorization retry cleanup, successful empty results and server errors. Live OAuth and Calendar acceptance is still required.
